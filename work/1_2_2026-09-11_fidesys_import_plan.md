# Корреляция roundtrip с импортом в препроцессор Fidesys 8.1

## Контекст

Для 1131 исходного `.fc` есть результаты строгого roundtrip. Пользователь
просит запустить установленный Fidesys 8.1 с `-model <исходный файл>`, собрать
ошибки консоли и после загрузки завершить созданный процесс и его окно.
Контрольные случаи: `Cube_static_direction_shell.fc` без ошибок,
`cube_multi.fc` с ошибкой пустого `mesh.elem_blocks`.

## Цель

Получить для каждого исходника лог препроцессора, ошибки импорта и статус,
затем сопоставить их с roundtrip по имени и SHA-256 файла.

## Источники истины

Инструкция пользователя и наблюдаемая работа его установленного Fidesys;
`AGENTS.md`; `work/1_2_2026-09-11_core_roundtrip_results.json`;
`docs/FC_INPUT_FORMAT.md`; предыдущий отчёт. Успешный импорт не меняет
приоритет пользователь → спецификация → библиотека → файл.

## Предполагаемые изменения

Диагностический скрипт, логи, объединённый JSON-реестр и отчёт в `work/`;
запись в CHANGELOG. Корпус, библиотека и спецификация не редактируются.
Рабочие файлы приложения направляются в отдельный временный каталог.

## Вопросы к пользователю

Для запуска дополнительных решений не требуется. Нужно технически установить,
можно ли получить положительный маркер завершения импорта. Отсутствие `[error]`
до истечения тайм-аута само по себе не доказывает завершённую загрузку;
неопределённые случаи должны быть выделены отдельно.

## План работ

1. Изучить launcher и выполнить два контрольных запуска.
2. Установить способ ожидания загрузки и закрытия принадлежащей запуску группы
   процессов; не затрагивать другие приложения пользователя.
3. Прогнать весь исходный корпус с ограничением времени каждого запуска,
   сохранять промежуточный результат и полный stdout/stderr.
4. Проверить полноту и контрольные суммы; построить перекрёстные группы
   roundtrip/импорт и частоты сообщений Fidesys.
5. Проверить инструмент, описать ограничения, обновить CHANGELOG.

## Проверки

Контрольные примеры пользователя; положительное подтверждение завершения
либо явный статус неопределённости; сохранение диагностики; отсутствие оставшихся
созданных процессов; SHA-256 исходников; полнота объединения 1131 записей.

## Риски

GUI может оставаться открытым после импорта, зависать или показывать модальные
ошибки. Ошибка лицензии/запуска не должна считаться ошибкой модели. Fontconfig
warning из примера пользователя — предупреждение окружения. При ускорении
через неграфический режим требуется сверка с обычным `-model` запуском.

## Уточнение методики после контрольных запусков

Локальная справка `preprocessor/bin/help/environment_control/session_control/
execution_command_syntax.htm` описывает `-nographics`, `-batch` и `-input`.
Используется тот же launcher с `-model`, дополненный этими параметрами.
Launcher преобразует `-model` во внутренний `-custom`: импорт выполняется
через `fidesys.silent_cmd('import fidesyscase ...')`.

После импорта выполняется короткий Python-файл из `-input`, печатающий
JSON-маркер с `cubit.get_error_count()`, числом узлов/элементов и версией API.
Это подтверждает завершение команды импорта; одного отсутствия сообщений
об ошибках недостаточно. Возвращаемое `True` команды также недостаточно:
оно наблюдается и при неудачном импорте. Launcher возвращает 11 и при
успехе, и при ошибке; код 11 сам по себе не классифицируется как отказ.

Ошибки GUI и batch совпали на четырёх контрольных случаях после исключения
номеров строк генерируемых команд. Основной прогон: восемь независимых
процессов одновременно, отдельный временный cwd, тайм-аут 60 секунд на файл.
Окон GUI при этом нет. Процессы нормально завершаются после probe; оставшаяся
группа при необходимости завершается SIGTERM/SIGKILL. Повторные проблемные
случаи проверяются последовательно с тайм-аутом 90 секунд.
