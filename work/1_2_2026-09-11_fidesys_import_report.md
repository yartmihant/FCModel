> Исторический снимок до исправления JSON. Два файла исправлены, один удалён; актуальный корпус содержит 1130 файлов. См. [результаты исправления](1_2_2026-09-11_json_cleanup_report.md).

## Результат для всех 1131 исходных файлов

- **450** загружены без ошибок препроцессора: **288** без предупреждений,
  **162** с предупреждениями.
- **679** завершили команду импорта с ошибками; модель могла загрузиться частично.
- **2** завершились до контрольного маркера, без текстовой ошибки.
  Их успешный импорт не подтверждён.
- **0** тайм-аутов. Все исходные SHA-256 совпали с результатами roundtrip.
  После завершения не осталось запущенных проверкой процессов препроцессора.

Основной прогон выполнен 11 сентября 2026, 15:10:26–15:17:42 MSK,
восемью независимыми процессами одновременно, примерно за 7 минут 16 секунд.
Проверялся импорт **исходных** файлов, не файлов после `fc_model.save()`.

## Сопоставление с roundtrip

В каждой строке перечислены все файлы соответствующей группы:

- **Roundtrip совпадает — 451:** Fidesys без ошибок **179** (39,7%),
  с ошибками **272**, незавершённых **0**.
- **Roundtrip различается — 611:** Fidesys без ошибок **265** (43,4%),
  с ошибками **346**, незавершённых **0**.
- **Roundtrip завершился ошибкой — 69:** Fidesys без ошибок **6** (8,7%),
  с ошибками **61**, незавершённых **2**.

Следовательно, **успешный roundtrip не является проверкой допустимости файла
для препроцессора**. Он проверяет сохранность JSON. В обратную сторону также
нет эквивалентности: **271** файл, не прошедший roundtrip (265 + 6), принят
препроцессором без ошибок. Это описательная статистика данного корпуса,
а не доказательство причины отдельных ошибок или оценка любых `.fc` файлов.

Для каждой записи JSON сохранены имя, исходная SHA-256, оба статуса,
точные уникальные ошибки и предупреждения, первичные ошибки без общих
`Command Failed.`/`Errors found during session.`, счётчик ошибок API,
количество узлов/элементов, длительность, код завершения, команда и путь к логу.
Числа сообщений API не обязаны совпадать с длиной списка уникальных текстов:
одно сообщение может повторяться, а общая ошибка команды учитывается отдельно.

Пакетный режим дублирует сообщения в `[error]` и `ERROR:`. В JSON эти повторы
объединены, в исходных логах сохранены полностью. В отдельном индексе групп
обобщаются только номера строк генерируемых команд и ID сущностей; точные
числа и тексты остаются в основном реестре и логах.

## Основные ошибки препроцессора

Количество означает число файлов с диагностикой; группы пересекаются:

- **417:** `Master entity is empty.`
- **206:** `Invalid element id <ID>.`
- **130:** `syntax error (<stdin>, line <N>)`.
- **83:** `There is no such Spring properties.`
- **81:** `Unrecognized Identifier: 'constant_damping'`.
- **50:** `Unrecognized Identifier: 'pure_lagrangian'`.
- **37:** `Invalid value specified.`
- **22:** исключение JsonCpp `requires objectValue or nullValue`.
- **10:** `Bad base64_encode('loads[1].apply_to').`
- **10:** конфликт/невыполненные prerequisites свойств материала.
- **10:** `Slave entity is empty.`
- **5:** `'mesh.elem_orders' field is empty.`
- **4:** `'mesh.elem_blocks' field is empty.`

Все остальные группы и связанные с ними имена файлов доступны в индексе ошибок.
Общие сообщения `Command Failed.` и `Errors found during session.` не выдаются
за самостоятельные причины.

Предупреждения есть в **331** файле: 162 из группы без ошибок и 169 с ошибками.
Наиболее частое — `The distance between nodesets is not accurate.` (**315** файлов).
Также встречаются сообщения об элементах в нескольких blocks, неэквивалентных
рёбрах/узлах и кривых нулевой длины. Они сохранены для отдельного разбора.

## Библиотека не загружает, а Fidesys принимает: 6 файлов

Пять случаев `KeyError: 'name'` при декодировании constraints:

- `Contact3dHex8EigenValuesTwoBlocks.fc`.
- `Contact3dHex8ShellEigenValues.fc`.
- `Contact3dHex8ShellEigenValuesCylindr.fc`.
- `Contact3dHex8ShellEigenValuesCylindr_MasterShell.fc`.
- `Contact3dHex8ShellEigenValues_MasterSlaveChange.fc`.

Все пять импортируются с нулём ошибок, но предупреждением о расстоянии
между nodesets. Это наблюдение о поведении препроцессора; решение о допустимости
пропущенного `name` в контракте библиотеки должно учитывать спецификацию.

Шестой — `Cube_dyn_direction_vector_findefs_vel.fc`: библиотека выдаёт
`dep_var_num shorter than data components`, а Fidesys загружает 27 узлов
и 8 элементов без ошибок и предупреждений.

Эти случаи — отдельная очередь для сверки контрактов и совместимости;
сами файлы в данном этапе не исправлялись.

## Связь конкретных roundtrip-расхождений с импортом

Здесь «без ошибок» относится к исходному файлу, до roundtrip:

- Потеря `property_tables[*].layers`: **8** без ошибок / **13** с ошибками.
- Потеря `direction_normal`: **31** / **126**.
- Потеря `thickness_change`: **16** / **29**.
- Уменьшение `property_tables` при повторных ID: **27** / **152**.
- Перестановка `mesh.elemids`: **14** / **26**.
- Удаление `contacts`: **59** / **1**.
- Добавление `additional_properties`: **89** / **283**.

Например, потерю описанных спецификацией слоёв нельзя целиком списать на
незагружаемые тесты: восемь исходников с таким roundtrip-расхождением проходят
импорт без ошибок. При этом отсутствие ошибки Fidesys не доказывает, что
импортёр сохранил все поля: он может нормализовать либо игнорировать часть данных.

## Незавершённые импорты

`Contact2dQUAD9.fc` и `Contact3dHEX27.fc` завершаются до контрольного маркера,
без `[error]`/`ERROR:`. Оба случая воспроизведены повторно, последовательно,
с лимитом 90 секунд: процесс заканчивается примерно за 3 секунды.
Оба также проверены обычным GUI-запуском и самостоятельно завершились
до принудительного закрытия. Причина завершения не установлена; это не тайм-аут
и не подтверждённый успешный импорт. Launcher возвращает 11, как и в остальных
запусках, поэтому его код не позволяет диагностировать причину.

Оба файла также не загружаются библиотекой из-за неизвестных кодов элементов.
В реестре сохранён статус `incomplete`, не подменённый утверждением о валидности
или недействительности модели.

## Некорректный JSON и небинарный режим

Все **12** исходников с `header.binary=false` вызывают ошибки препроцессора
и не загружаются библиотекой. Спецификация описывает этот режим, поэтому
результат относится к данной реализации импорта; автоматически удалять
поддержку режима из спецификации на этом основании нельзя.

Из трёх файлов, не разобранных строгим JSON-парсером:

- `Contact2dQuad8_CGS1_regular_notconform_nogap_tension_PL.fc`:
  Fidesys доходит до ошибки `pure_lagrangian`.
- `Contact3dHex8_Tied_RBE2_findefs_Penalty.fc`:
  Fidesys доходит до `Invalid element id 3.` и частично загружает сетку.
- `EfPrCond_OrthogReinforced_Tet10_per.fc`:
  `FC parse failed.`, ноль узлов/элементов.

Таким образом, два исходника с лишними запятыми Fidesys разбирает достаточно
далеко, чтобы выдать ошибки модели; это не делает их корректным стандартным JSON.

## Методика, подтверждение завершения и воспроизведение

Использован установленный пользователем launcher:

```bash
/home/antonov/.bin/CAE-Fidesys-8.1/cae-fidesys-8.1 \
  -nographics -batch -model /absolute/path/to/original.fc \
  -input /temporary/path/after_import.py
```

Параметры batch/nographics/input описаны в поставляемой локальной справке
`preprocessor/bin/help/environment_control/session_control/execution_command_syntax.htm`.
Launcher выполняет тот же путь `-model` → `-custom` → `import fidesyscase`.
В конце отдельный Python-файл печатает JSON-маркер `FCMODEL_IMPORT_DONE=`:
счётчик `cubit.get_error_count()`, число узлов/элементов и `cubit.get_version()`.

`loaded_without_errors` требует одновременно маркера завершения,
нулевого счётчика API, отсутствия консольных ошибок и наблюдаемого нормального
кода launcher (0 или 11). В этом прогоне **все** коды — 11. Возвращаемое
командой `True` тоже не означает успешный импорт: оно печатается и после ошибок.
Все 450 загрузок без ошибок содержат ненулевые узлы и элементы.

Обычный GUI-запуск проверен на шести файлах: двух примерах пользователя,
двух дополнительных моделях с ошибками и двух незавершённых случаях.
На четырёх завершённых контрольных импортах первичные ошибки GUI/batch совпали;
отличаются лишь номера строк внутренних команд. Fontconfig warning из GUI
является сообщением окружения и не учитывается как ошибка модели.

Каждый файл открывается в новом процессе и временном рабочем каталоге.
Лимит основного прогона — 60 секунд. По окончании batch процесс завершается
сам, оставшаяся группа при необходимости закрывается SIGTERM/SIGKILL.
Исходные модели и пользовательские процессы не используются как цели записи
или завершения. Графические контрольные окна закрыты.

[Скрипт прогона](fidesys_import_audit.py):

```bash
PYTHONPATH=src:work python work/fidesys_import_audit.py \
  --output work/1_2_2026-09-11_fidesys_import_next --workers 8
```

Выходной каталог должен быть новым; `--resume` продолжает имеющийся checkpoint.
`--only <имена.fc>` позволяет повторить выбранные файлы, `--timeout` задаёт
лимит на файл. Код скрипта 1 означает наличие проблем в корпусе и ожидаем
для текущего набора. В отличие от кода launcher, это код диагностического скрипта.

Сохранены [метаданные](1_2_2026-09-11_fidesys_import/metadata.json),
[контрольные суммы launcher/импортёра](1_2_2026-09-11_fidesys_import/installation.json),
логи и промежуточный `checkpoint.jsonl`. Каталог продукта называется 8.1;
низкоуровневый `cubit.get_version()` сообщает `2021.11` — это отдельно
сохранённая версия API, не переименование выпуска CAE Fidesys.

## Проверки и ограничения

- Все **1131** записи однозначно соединены с roundtrip по имени и SHA-256;
  для каждой есть полный лог. Итоговая повторная SHA-256 проверка подтвердила
  неизменность всех исходников.
- **13** тестов нового инструмента проходят на Python 3.8 и 3.12:
  разбор/дедупликация ошибок, обязательный маркер, статусы, тайм-ауты,
  прекращение дочернего процесса, целостность источника и агрегация.
- Pyright новых файлов: **0 ошибок**.
- Штатный pytest: прежние **194 passed / 2 failed**
  (`test_load_apply_remapped`, `test_tetra4_properties`).
- Pyright пакета и штатных тестов: прежние **19 ошибок** в существующих тестах.
  Логи находятся рядом с результатами: `audit_tests.log`, `audit_tests38.log`,
  `audit_pyright.log`, `pytest.log`, `pyright.log`.

Сверены правила проекта, предыдущий реестр, LLM-контекст, API-индекс,
локальная справка Fidesys и соответствующие места спецификации.
В частности, спецификация явно перечисляет `pure_lagrangian`/`aug_lagrangian`,
но данный препроцессор отвергает эти идентификаторы. Это расхождение описанного
формата и данного импортёра; оно не доказывает отсутствие поддержки в решателе.
Сам решатель не запускался. Не проверялись физическая корректность,
полнота сохранения всех импортированных атрибутов и импорт roundtrip-выходов.

Приоритет остаётся прежним: **решение пользователя → спецификация →
библиотека → файл**. Код библиотеки, корпус, спецификация и VERSION не менялись;
наблюдения и результаты добавлены в `[Unreleased]` CHANGELOG.
