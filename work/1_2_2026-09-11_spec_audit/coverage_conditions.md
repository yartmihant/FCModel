# Охват аудита условий

`audit_conditions.py` проверяет только назначенные секции `.fc`: `loads`, `restraints`, `initial_sets`, `coupling_constraints`, `contact_constraints`, `periodic_constraints` и `receivers`. Верхнеуровневые ключи, `header` в целом, `settings`, JSON-совместимость и неизвестные верхние секции остаются ответственности root-аудитора.

Проверены документированные таблицы типов нагрузок (строки 1067–1139), `restraints.flag` (1169), типы initial sets (1225), coupling constraints (1245–1315), contact constraints и ограничения числовых полей (1324–1405), periodic constraints (1414–1441), receivers (1448–1468), компонентную модель зависимостей (1812–1834), алиасы и legacy-синонимы (1992–2005), а также sentinel `apply_to="all"`. Для бинарных payload проверяется валидный Base64, кратность размеру `header.types.int` и согласование с `*_size`; пары поверхностей допускают два числовых значения на одну сущность.

Не проверяются существование узлов/elements, физическая корректность, нормализация направления, endian, существование всех ссылочных `cs`, наличие необязательных полей, соответствие `data` фактическим DOF в случаях, где спецификация описывает компонентную раскладку неполно, и семантика solver-а. Неизвестные enum/dependency коды дают `ambiguity`, поскольку спецификация не всегда формулирует закрытое множество. Отсутствующие записи не считаются ошибками; Совместимый coupling alias coordinate_system_id отмечается отдельно как legacy-предпочтение имени cs; контактные синонимы равноправны.

Итоговые результаты берутся из `results.json`; статистика раннего пилотного модуля не является финальной. После интеграционного ревью root добавлены проверки всех присутствующих скалярных/массивных типов step/case, initial flags/data, вложенных lagrange_settings/gap_gas_fractions, coupling equation terms и DOF, строгое отклонение некорректного Base64, scalar/table layout и размеров значений/аргументов. Face/segment/periodic targets проверяются как пары; point targets — тройки double. Отсутствующая ширина типа не заменяется предполагаемой шириной. `ignoreoverlap` — допустимый синоним, не legacy. Разрешён initial apply_to=all. Неизвестные компоненты и неописанные варианты хранения получают ambiguity.

Для числовых компонентов в binary=false найденная строка вместо массива отмечается как ambiguity границы основной схемы и раздела компонентного кодирования. Нулевые/пустые числовые компоненты разрешены по строке 1832. Для scalar constant допускаются пустой либо одноэлементный буфер. Отсутствующие необходимые для интерпретации metadata отмечаются ambiguity; полная обязательность этих полей документом не формализована.
