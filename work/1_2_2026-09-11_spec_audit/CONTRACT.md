# Контракт модулей аудита

Все файлы проверяются напрямую как JSON, независимо от FCModel и Fidesys. Не менять корпус, src, docs, VERSION, git, CHANGELOG (changelog ведёт root).

Каждый модуль `audit_<domain>.py` экспортирует `audit(data: dict) -> list` (используйте Python >=3.8 совместимые аннотации `Dict`, `List`, `object`, без Any). Результат — список JSON-совместимых словарей. Ошибки входных данных должны давать находки, а не исключения. Модуль может иметь свои небольшие вспомогательные функции. Не читать файлы и не запускать аудит при импорте. Root запустит каждый модуль на каждом файле.

Находка содержит все поля:

```json
{"rule":"MAT.GROUP_TYPE", "severity":"violation", "path":"$.materials[0].elasticity[0].type", "message":"Русское описание: что найдено и что ожидается", "actual":42, "expected":"0, 1, ...", "spec":"docs/FC_INPUT_FORMAT.md:553"}
```

Severity: `violation` — прямое противоречие однозначному актуальному требованию; `legacy` — документированная устаревшая структура; `ambiguity` — пробел/противоречие/неопределённость спецификации, препятствующие заключению. Неизвестные ключи/коды считать ambiguity, если документ не говорит о закрытом множестве. Обычные показанные типы обязательны для присутствующих полей; не объявлять все поля примеров обязательными без текстового основания. Отсутствующее обязательное для интерпретации поле можно отметить ambiguity при неясной обязательности. bool не считать int; целочисленные float разрешены для int, дробные/нечисловые значения запрещены; int считать допустимым double. Пустые секции не требуют заполнения опциональных полей. Длинные actual сокращать до краткого свидетельства (длина, значения нарушений), не выводить мегабайты Base64.

Файл `coverage_<domain>.md`: перечислить проверенные пункты документа, коды правил и ограничения/неясности. Файл `test_<domain>.py`: целевые проверки правил и минимум одного допустимого случая, pytest. Избегать выдуманных требований по физике, нормализации или обязательности.

Буферы: основная спецификация разрешает plain JSON при binary=false; материалы/компоненты имеют особую схему в строках 1812–1834. Для строгой проверки Base64 допустим стандартный base64.b64decode(validate=True); если декодируете значения через библиотеку, импортировать FCValue только из fc_model. Запрет обхода FCValue относится к сериализации библиотеки: не менять сериализацию и не перекодировать исходники. Независимая проверка сырых байтов необходима для выявления не принимаемых библиотекой входов. Размер elem_types — фиксированный uint8 (один байт); остальные размеры типов брать из header.types; не предполагать 4/8 без фиксации отсутствия размеров как неопределённости. Порядок байтов документирован не полностью: фиксировать ограничение, не выводить ошибку файла только из предположения об endian.

Root отдельно проверяет top-level, header, settings, JSON, неизвестные верхние секции. Не дублируйте эти области. Модули отвечают только за назначенные разделы. Общие требования к новым расширениям и неизвестным полям применяйте аккуратно, учитывайте legacy и aliases из конца документа. В аудит не включать выводы из результатов прежних двух тестов.

Согласованные поправки 2026-09-11: output-настройки опциональны и взаимоисключающи; число объектов группы материала не ограничено одним; eigen solver=`auto`. Глобальные DOC.DIMENSIONS_CONFLICT и MESH.BINARY_SEMANTICS_UNCHECKED исключены из находок файлов; соответствующие ограничения описываются в документации охвата.
