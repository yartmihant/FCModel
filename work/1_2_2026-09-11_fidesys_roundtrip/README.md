# Roundtrip всех 1130 моделей через Fidesys 8.1

## Результат и критерий

Выполнен новый реальный прогон: импорт исходного FC и экспорт FC в отдельном процессе препроцессора. **450 моделей прошли цикл без ошибок; 678 имеют ошибки импорта; у двух импорт не подтверждён.** Все прежние 450 успешных импортов также успешно экспортировались. Новых отказов экспорта среди них нет.

По решению пользователя успешные модели считаются **живыми и неустаревшими** и образуют набор для калибровки. Это операционный критерий: оба маркера завершения получены, ошибки отсутствуют, API сообщает нулевые счётчики, команда экспорта выполнена и созданный FC читается как строгий JSON с header/mesh и корректными полями количества узлов/элементов. Возвращаемое командой True, наличие файла или код launcher отдельно не являются доказательством успеха.

Строгое равенство JSON проверено отдельно: **ни один из 450 успешных экспортов не совпал с исходником**. Это не отменяет операционный успех. Fidesys добавляет defaults, удаляет поля и меняет представление данных. Например, у Cube_static_direction_shell.fc только два различия: имя глобальной системы координат переведено на английский, поле header.fidesys_version удалено. Компаратор сохраняет прежнюю строгую семантику: игнорирует порядок ключей, но учитывает типы, порядок массивов, значения и наличие полей.

Создано 1128 выходных файлов: 1097 читаемых FC и 31 некорректный выход. Ещё в двух случаях экспорт не начался. Читаемый выход после ошибочного импорта **не считается живой моделью**. Все неуспешные выходы сохранены для исследования частичных экспортов.

## Артефакты

- `results.json` — полный реестр обоих этапов, ошибок/предупреждений, выходных файлов и различий JSON.
- `exported/` — все созданные FC под исходными именами; исходный корпус не перезаписывался.
- `alive_files.txt` — 450 имён живых моделей, по одному на строку.
- `alive_manifest.json` — те же модели с хешами оригинала/экспорта и относительным адресом экспортированного файла.
- `logs/` — 1130 полных stdout/stderr-журналов.
- `checkpoint.jsonl`, `metadata.json` — checkpoint и параметры запуска, хеши исполняемых файлов/инструмента, таймаут и число процессов.
- `difference_patterns.json` — частые пути изменений среди живых моделей; это различия, не автоматически дефекты экспортёра.
- `verification.json`, `verify.py`, `previous_analysis_hashes.json` — независимая сверка всех исходников, выходов, логов и строк CSV, подтверждение сохранности прежних колонок fc-model/спецификации.

## Таблица и калибровка

`../1_2_2026-09-11_test_summary.csv` пересобран: 1130 строк, **45 столбцов**. Данные простой загрузки Fidesys заменены результатами полного цикла. Добавлены признак живой модели, завершение экспорта, читаемость выходного FC, ошибки по этапам и при чтении экспорта, экспортированные количества узлов/элементов, отдельный статус и подробности JSON-сравнения. Служебные пути/хеши/времена и постоянные столбцы не возвращались.

`Fidesys_живая_модель=Да` означает принятый набор калибровки; `Не подтверждено` не является самостоятельным доказательством устаревания. `Fidesys_выход_FC_валиден` отражает читаемость строгого JSON/header/mesh/счётчиков, а не проверку всей спецификации или физики. `Fidesys_экспорт_завершён=Да` означает достижение маркера команды, даже если команда сообщила ошибки. Статус полного цикла учитывает их.

Колонка `Fidesys_ошибок_по_API` теперь содержит суммарный счётчик на завершении экспорта; без этого маркера значение неизвестно и оставлено пустым. Импортные/экспортные сообщения разделены. Загруженные узлы/элементы по-прежнему относятся к маркеру импорта; экспортные счётчики прочитаны из выходного JSON.

Сравнение загруженной сетки с исходным JSON: 1097 совпадений, 31 расхождение, 2 неизвестных результата. **У всех 450 живых моделей числа узлов и элементов совпадают на всех трёх стадиях: исходник, импортный API, экспортированный FC.** Геометрическое/семантическое равенство mesh при переупорядочении не утверждается.

Среди живых моделей библиотечный roundtrip: 179 совпадений, 265 расхождений, 6 исключений. По текущим правилам спецификации: 239 с violation, 135 только с legacy/неясностями, 76 без находок. Эти наблюдения сохранены без изменений и нужны для дальнейшей калибровки; они не переопределяют решение пользователя об актуальности успешно прошедших моделей. Автоматических исправлений прочих пунктов спецификации или библиотеки не выполнялось.

Предупреждение `The distance between nodesets is not accurate` игнорируется на обоих этапах, остальные сохраняются. Исторические журналы остаются необработанными доказательствами исходного вывода. Прежние реестры простой загрузки не удалены; сборщик текущей таблицы их больше не использует.

## Метод и контрольные прогоны

Команда для каждого исходника: установленный launcher с `-nographics -batch -model <source.fc> -input <export_fc.py>`. Python-проба сначала печатает импортный маркер и API-счётчики, затем выполняет `cubit.cmd('export fidesyscase "<output.fc>" overwrite')`, затем печатает экспортный маркер, результат команды и счётчики. Каждый кейс получает отдельные cwd, process group, файл экспорта и лог. После завершения/таймаута группа процессов закрывается, исходный SHA-256 проверяется повторно.

Использован синтаксис экспорта из предоставленного пользователем `../1_2_test_roundtrip.jou`; этот журнал и файлы пользователя в data/tmp не менялись. Перед полным прогоном проверены Cube_static_direction_shell.fc, Contact2dQuad4Quad8HomogeneousStress.fc и cube_multi.fc. Первые два успешно экспортированы и затем повторно импортированы без ошибок. cube_multi.fc вернул True от команды, но создал пустой файл с ошибками — отрицательный контроль классификатора. Результаты находятся в соседних каталогах `..._pilot/` и `..._controls/`.

Полный прогон: 8 процессов, таймаут 60 секунд на кейс. Contact2dQUAD9.fc и Contact3dHEX27.fc дополнительно повторены последовательно с таймаутом 90 секунд (`../1_2_2026-09-11_fidesys_roundtrip_retry/`): вновь завершились до импортного маркера, без экспорта. Это не успешные нулевые модели. Остаточных запущенных нами процессов Fidesys не обнаружено.

## Проверки и воспроизведение

26 целевых тестов (12 новых тестов стадий/экспорта и 14 прежних тестов импорта) проходят. Включены отрицательные случаи True при ошибке, отсутствующий/ложный маркер, некорректный выход, авария/таймаут, разделение сообщений, сохранность исходника и запрет повторного использования существующего экспорта. Pyright инструмента, тестов и verifier — 0 ошибок.

Штатные проверки сохраняют прежние 194 passed / 2 failed (`test_load_apply_remapped`, `test_tetra4_properties`) и 19 ошибок типов в штатных тестах. Логи здесь: `target_pytest.log`, `pyright.log`, `verify_pyright.log`, `project_pytest.log`, `project_pyright.log`. Код пакета не менялся.

Независимо подтверждены: все 1130 SHA-256 исходников, все хеши экспортов, маркеры/сообщения 1130 логов, классификация живых моделей, строгое JSON-равенство, значения новых колонок и неизменность остальных аналитических колонок. Матрица проведена через Artifact Tool, изменённые столбцы просмотрены визуально. CSV сохраняет все различия без дополнительного сокращения; большие исходные значения представлены компактно общим компаратором (prefix/length/hash).
