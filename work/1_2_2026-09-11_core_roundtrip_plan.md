# Первичная проверка input-output корпуса ядра Fidesys

## Контекст

Пользователь предоставил `data/fc_core_tests`: 1131 файл `.fc` (около 91 MiB).
В корпусе возможны устаревшие случаи. Приоритет решений: пользователь →
`docs/FC_INPUT_FORMAT.md` → библиотека → входной файл.
Рабочее дерево уже содержит изменения документации; они сохраняются.

## Цель

Для каждого файла выполнить `FCModel.load(path)` → `model.save(output)`
и сравнить разобранные JSON. Игнорируется только порядок ключей объектов
(и лексическое оформление JSON). Порядок массивов, наличие полей, значения
и типы скаляров сохраняются: `1` и `1.0` считаются разными представлениями.

## Источники истины

`AGENTS.md`, `VERSION`, `docs/FC_INPUT_FORMAT.md`, README, обе формы LLM-контекста,
`src/fc_model/__init__.py`, `tests/test_round_trip.py`, текущий changelog.
Существующий `deep_diff` допускает потерю некоторых пустых полей и для этой
проверки не подходит.

## Предполагаемые изменения

Отдельный воспроизводимый диагностический скрипт и отчёт в `work/`, запись
в `[Unreleased]`. Исходный корпус, библиотека и спецификация не корректируются
на этапе измерения. Сохранённые модели пишутся в отдельный каталог вне корпуса.

## Вопросы к пользователю

Для первоначального прогона не требуется дополнительных решений.
После получения результатов: какие расхождения исправлять в библиотеке,
какие в корпусе и какие требуют уточнения спецификации? Сам факт расхождения
не доказывает, что тест устарел.

## План работ

1. Инвентаризировать все файлы рекурсивно.
2. Проверить исходный JSON, выполнить публичные load/save, прочитать результат.
3. Собрать все структурные расхождения с путями JSON Pointer и краткими значениями;
   ошибки классифицировать по этапу и месту исключения. Продолжать после ошибки файла.
4. Зафиксировать SHA-256 исходников до/после, сводку и детали каждого случая.
5. Сверить ведущие причины с кодом и спецификацией, записать ограничения выводов.
6. Проверить скрипт, выполнить штатные pytest/pyright и обновить changelog.

## Проверки

Сравнение не разрешает исчезновение пустых полей, сортировку массивов или
декодирование Base64 для ослабления критерия. Повторные ключи и не-JSON числа
NaN/Infinity выявляются до сравнения. Проверки компаратора включают перестановку
ключей, массивы, типы и пропущенные пустые значения.

## Риски

Первое исключение скрывает последующие проблемы файла. Различие Base64 пока
не определяет, поменялось ли содержимое или только представление. Нет запуска
решателя Fidesys и заключения о физической корректности задач. В LLM-контексте
указана версия 1.2.0, хотя VERSION содержит 1.2.7; это существующее расхождение,
предлагается синхронизировать отдельно.
