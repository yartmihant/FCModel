# Проверка всего корпуса по спецификации FC

## Контекст

Пользователь поручил проверить каждый из 1130 текущих файлов по `docs/FC_INPUT_FORMAT.md`, независимо от результатов Fidesys и roundtrip, дополнить существующий CSV и предложил распределить проверку между Luna.

## Цель

Воспроизводимая проверка каждого файла, унифицированные находки с JSON-путём, основанием в спецификации и разграничением нарушения, legacy и неопределённости документа.

## Источники истины

Решения пользователя выше спецификации; спецификация выше кода и примеров корпуса. Основание аудита — текущая спецификация с SHA-256. Код используется только как техническое средство, не как определение допустимости. Успешный импорт и roundtrip не считаются доказательствами соответствия.

## Предполагаемые изменения

Инструменты, правила, реестр и протокол перепроверки в `work/1_2_2026-09-11_spec_audit/`; новые столбцы в существующем `work/1_2_2026-09-11_test_summary.csv`; запись в CHANGELOG. Файлы корпуса, библиотека и спецификация не исправляются в рамках проверки.

## Вопросы к пользователю

Блокирующих вопросов нет. Обнаруженные неясности спецификации сохраняются как отдельные находки для последующего решения пользователя, без самостоятельного изменения формата.

## План работ

1. Зафиксировать общий контракт находок, разделить проверку документа на независимые области для трёх Luna.
2. Подготовить проверяемые правила с указанием строк спецификации; явно описать охват и ограничения.
3. Выполнить все области проверки на всех 1130 файлах; проверить JSON, структуру, перечисления, размеры буферов и документированные связи.
4. Независимо перепроверить Luna небольшие группы файлов из разных сочетаний результатов, проверить положительные и отрицательные примеры правил.
5. Объединить находки с сохранением всех прежних столбцов CSV, сверить хеши и полноту строк.
6. Зафиксировать ограничения, итоги, проверки и changelog.

## Проверки

Каждый файл получает результат каждой области или явный статус ошибки проверки. Сверяются хеши исходников, спецификации и предыдущей таблицы. Тесты проверяют реальные ошибки правил и границы, а не повторяют реализацию. CSV повторно читается независимым парсером. Проверяются новые инструменты и штатные проверки согласно AGENTS.md.

## Риски

Документ не является формальной полной JSON Schema: обязательность многих полей и некоторые структуры не определены. Неизвестное поле означает пробел документации, а не автоматически ошибку файла. Legacy поддержка отделяется от актуального v3. Нельзя заявлять полное соответствие там, где остаются непроверяемые требования. Геометрическая/физическая корректность и успешное решение задачи не следуют из соответствия формату.
